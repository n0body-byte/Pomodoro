# Agent 截止约束说明

## 为什么需要本地截止约束

此前“截止时间”只作为文字发送给模型，本地容量评估仍完全使用用户设置的可用分钟。若距离截止只剩 60 分钟、用户却保留 120 分钟可用时间，模型和本地质量门可能得到互相矛盾的结论。

现在 App 会先在本地解析截止时间，再使用以下规则得到真正参与规划的容量：

`有效可用分钟 = min（手动可用分钟，距截止剩余分钟）`

有效容量会同时进入 DeepSeek 上下文、本地应急计划、计划健康度、质量门和压缩计划提示。解析与校验均在本地完成，不产生 Token 消耗。

## 支持的输入

- 绝对时间：`2026-08-25 18:00`、`2026/08/25 18:00`
- 相对日期：`今晚 22:00`、`今天 23:00`、`明天 18:00`、`后天 18:00`
- 星期：`周五 18:00`；当天时间已过时自动解释为下周同一天
- 相对时长：`2小时后`、`90分钟后`

相对时间会在发起请求前转换为绝对的 `YYYY-MM-DD HH:mm`，随后随 Agent 会话和跨设备快照保存，避免第二天重新打开时含义漂移。

## 保护策略

- 无法识别的输入会给出可用格式，不调用 AI。
- 截止时间已过时，生成、调整和本地兜底都会暂停，要求用户更新或清除截止时间。
- 截止时间比手动可用时间更紧时，页面明确展示收紧前后的分钟数。
- 不填写截止时间时保持原有逻辑，只按手动可用分钟规划。

自动化测试覆盖绝对时间容量收紧、中文相对时间标准化、过期拒绝和格式错误提示。当前项目结果为 `60/60` 通过，且 `assembleHap` 构建通过。
