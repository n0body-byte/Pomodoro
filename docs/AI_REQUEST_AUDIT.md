# DeepSeek 调用审计说明

## 解决的问题

仅看到 AI 回复，用户难以判断应用是否真正调用了 DeepSeek、使用了哪个模型、消耗了多少 Token，以及计划是否被本地质量门拦截。调用审计把这条链路变成可检查证据。

## 记录内容

每个 Agent 会话最多保留最近 20 次 DeepSeek 调用，页面默认展示最新结论，展开后显示最近 5 条：

- 动作类型：生成计划、调整计划、执行复盘或质量门自动修复；
- 服务商与实际请求模型；
- 请求开始时间与端到端耗时；
- 服务端返回的输入、输出和总 Token；
- 结果状态：已采用、质检拦截、修复后采用或调用失败；
- 不包含用户提示词、对话正文和 API Key。

## 如何理解状态

“已收到 DeepSeek 响应”表示应用拿到了可解析的远端结果，或服务端返回了非零 usage。计划被“质检拦截”仍可能已经产生 Token，因为模型请求已经执行，只是结果没有通过本地质量门。

“请求未取得可确认的远端 usage”常见于网络失败、鉴权失败、限流或服务端未返回 usage。它不擅自声称已经计费，用户可结合错误信息、连接诊断和 DeepSeek 控制台进一步核对。

调用记录用于应用内可观测性，不替代服务商账单；服务商控制台的余额或用量展示可能存在刷新延迟。

## 持久化与跨设备

记录随当前 Agent 状态与历史对话保存，新对话拥有独立审计链。HarmonyOS 应用接续会迁移当前会话的调用记录，但仍不会迁移 API Key。

调用审计中的 `usage.total_tokens` 同时进入对话级 Token 预算；达到上限后会阻止新的 DeepSeek 请求。详见 [DeepSeek Token 预算说明](AI_TOKEN_BUDGET.md)。

单元测试覆盖 usage 捕获、远端响应判断和最近 20 条上限。当前项目共 `73/73` 项单元测试通过，HAP 构建通过。
