# 穿戴协同与模拟心率原型

## 当前定位

当前版本面向“暂无智能手表真机”的开发阶段，提供可运行的虚拟手表和模拟心率闭环。它用于验证手表交互、状态同步、隐私过滤、规则判断和 Agent 调整入口，不宣称已经读取真实设备心率。

入口位于“设置 > 穿戴协同实验室”，不会增加新的底部 Tab。

## 已完成能力

- 虚拟手表同步展示当前任务、专注/休息状态和剩余时间。
- 可从虚拟手表开始、暂停或跳过当前计时阶段。
- 内置平稳专注、压力升高、运动干扰和设备断连四种确定性场景。
- 本地规则会区分持续负荷、运动干扰和不可用数据，不因单次读数直接改写计划。
- 压力场景允许先暂停计时，或将聚合摘要带入 Agent 页面，由用户确认后再发送。
- 发送给 Agent 的内容只包含窗口中位数、个人基线、持续高负荷时间和运动标记，不包含逐秒心率。

## 分层结构

```text
HeartRateProvider
├── MockHeartRateProvider     当前使用
└── RealHeartRateProvider     真机和权限确认后实现
          ↓
WearableHealthHelper         本地规则与隐私摘要
          ↓
WearableLab                  虚拟手表和用户确认
          ↓
Index / AiPlanner            计时控制与计划调整
```

`HeartRateProvider` 是数据源边界。接入真机时，应在新的实现中完成订阅、权限检查、佩戴状态与信号质量处理，并在生命周期结束时取消订阅；业务规则和页面不应直接依赖传感器 API。

## 安全规则

1. 设备断连、未佩戴、信号质量不足或样本过少时，不允许调整计划。
2. 心率升高并伴随活动时，标记为运动干扰，只建议观察。
3. 窗口心率中位数高于个人基线至少 20 BPM，且持续至少 120 秒时，才建议暂停恢复。
4. 所有计划调整均需要用户确认；应用不自动完成、删除或大幅改写任务。
5. 该功能不进行医学诊断，也不替代专业健康建议。

## 真机接入验收清单

- 确认目标手表属于智能穿戴或轻量级穿戴，并确定对应应用模型。
- 确认开发者账号能够申请实时健康数据权限。
- 验证安装、授权、佩戴、熄屏、断连和重连流程。
- 用真实静息、专注和运动场景校准基线及阈值。
- 检查长时间订阅的功耗，并确保离开页面或 Ability 时取消订阅。
- 只有完成上述验证后，才在作品材料中表述为“真实心率接入”。
