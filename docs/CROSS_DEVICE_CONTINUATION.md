# 跨设备接续说明

## 能力边界

本项目使用 HarmonyOS `UIAbility.onContinue` 实现应用接续原型。用户从系统接续入口把应用迁移到另一台可信设备后，可以继续当前工作；它不等同于多台设备同时在线、实时互相同步的云服务。

当前模块声明支持 `phone`、`tablet` 和 `2in1`，并启用 `continuable`。实际接续需要两台满足系统要求的设备、相同应用版本、正确签名以及系统侧的可信设备组网。

## 迁移内容

| 数据 | 处理方式 |
|---|---|
| 当前计时 | 保留阶段、运行状态和绝对 `deadlineAt`，目标端根据真实时间恢复 |
| 本轮任务 | 迁移任务、项目、标签、备注、预计番茄数和 Agent 来源 |
| Agent 状态 | 迁移当前对话、计划、执行进度、记忆、质量状态与回退快照 |
| 对话上下文 | 只保留当前 Agent 最近 8 条消息，每条最多 2000 字符 |
| 专注历史 | 迁移最近 50 条记录，并与目标端历史幂等合并 |
| API Key | 不迁移、不持久化，目标设备需要重新输入 |

## 可靠性设计

- 整体快照上限为 60000 个字符，避免接近系统 Want 参数容量边界。
- 快照带 `schemaVersion`，不兼容版本会被拒绝，不会覆盖本地数据。
- `transferId` 防止同一次接续重复应用；历史记录再按记录 ID 或“完成时间 + 类型”去重。
- 无活动计时的快照会清理目标端旧计时，避免恢复出并不存在的阶段。
- 运行中计时使用绝对截止时间，而不是复制静态剩余秒数，迁移过程本身也计入时间流逝。
- 日志只记录成功或失败状态，不输出对话内容、任务详情或 API Key。

## 验证方式

自动化测试覆盖绝对截止时间保留、最近上下文裁剪、错误版本与损坏 JSON 拒绝、历史记录幂等合并。当前结果为 `44/44` 通过，且 `assembleHap` 构建通过。

真机联调建议按以下顺序检查：

1. 在设备 A 启动一个带任务的专注阶段，并生成或恢复一份 Agent 计划。
2. 通过系统应用接续入口迁移到设备 B。
3. 确认设备 B 的倒计时扣除了迁移耗时，任务和计划仍一致。
4. 完成一个番茄，确认统计只新增一次，并能继续推进所属 Agent 步骤。
5. 重复触发同一接续，确认专注历史和累计时长没有重复增加。
6. 确认设备 B 未自动获得 DeepSeek API Key。

仓库提供的是未签名 HAP，因此双真机演示前需要在 DevEco Studio 中配置团队签名并在两台设备上安装同一构建。
