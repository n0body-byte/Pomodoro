# Agent 执行核验说明

## 为什么需要核验

完成一个或多个番茄只证明用户投入了时间，不代表步骤的完成标准已经满足。应用因此把“预计专注量达标”和“成果完成”分成两个状态，避免 Agent 基于错误前提继续规划。

## 使用流程

1. AI 计划步骤达到预计番茄数后，计时页显示“待核验”，引导回到 AI 页面。
2. 用户填写具体结果，并选择“已形成交付”“部分完成”或“遇到阻塞”。
3. 本地质量门拒绝“完成了”“有问题”等空泛描述，要求文件名、完成数量、提交状态、当前进度或明确错误等可复盘信息。
4. 选择部分完成或遇到阻塞时，该步骤会恢复为未完成，不会虚增计划进度。
5. 用户主动复盘，或在已明确开启自动复盘时，应用才会把核验结果发送给 DeepSeek。

## Agent 如何使用结果

- 已形成交付：先核对记录是否满足步骤原有完成标准，再推荐下一步。
- 部分完成：保留真实进度，拆小剩余工作并重新估算。
- 遇到阻塞：不给出泛化鼓励，优先生成解除阻塞所需的检查、沟通或替代动作。

核验记录随 Agent 当前状态和历史对话持久化，也会随 HarmonyOS 应用接续迁移；DeepSeek API Key 始终不在其中。

## 自动化验证

单元测试覆盖可核验描述接收、空泛描述拒绝、部分完成步骤回退、阻塞证据进入复盘提示，以及新鲜停止阶段的一键启动门。当前项目共 `70/70` 项单元测试通过，HAP 构建通过。
